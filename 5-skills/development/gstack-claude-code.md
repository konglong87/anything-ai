## 📖 简介

**Gstack** 是 YC 总裁 Garry Tan 开源的 **Claude Code 技能包**，非新模型、非提示词合集，内置 **26个斜杠命令**，覆盖头脑风暴、产品审视、架构设计、代码审查、测试、发布的开发全流程，可单人通过终端完成产品、架构、设计、测试、安全审计相关工作。

## ✨ 核心功能

### 1. YC创业导师视角
- `/office-hours`：深挖需求真实性，锁定MVP切入点
- 对抗式追问验证需求
- 输出多套产品方案对比

### 2. 多维度审查系统
- `/plan-ceo-review`：投资人/CEO视角
- `/plan-eng-review`：工程视角
- `/plan-design-review`：UI设计评估

### 3. 自动化文档生成
- `/design-consultation`：生成 DESIGN.md、CLAUDE.md
- 工程架构文档
- UI设计系统文档

### 4. 开发测试工具
- `/review`：代码/安全审查
- `/qa`：自动化测试
- `/ship`：一键发布
- `/retro`：工程复盘

## 🚀 真实核心步骤

### 阶段1：需求与产品定义
1. 执行 `/office-hours` + 项目完整需求
2. 按追问如实反馈真实用户案例、痛点、需求依据
3. 确认MVP方案，完成设计文档初审

### 阶段2：产品战略与风险管控
1. 执行 `/plan-ceo-review`，选择**选择性扩展**模式
2. 确认架构选型、安全方案（数据库只读限制）
3. 输出错误故障地图、产品10x扩展方向

### 阶段3：工程架构落地
1. 执行 `/plan-eng-review`
2. 确认技术栈、项目结构、数据库选型
3. 生成工程规范、接口合约、项目目录

### 阶段4：UI设计标准化
1. 执行 `/plan-design-review` 完成UI评估
2. 执行 `/design-consultation` 生成完整设计系统文档

### 阶段5：开发测试与发布
1. 执行 `/review` 排查代码与安全漏洞
2. 执行 `/qa` 完成自动化浏览器测试
3. 执行 `/ship` 一键创建PR发布
4. 执行 `/retro` 完成工程复盘

## 💡 核心命令详解

### `/office-hours` - YC创业导师视角

**功能**：模拟YC创业导师，深挖需求真实性，锁定MVP切入点

**使用示例**：
```
/office-hours

我有一个想法：做一个AI科研文献分析工具，帮助研究人员快速发现研究空白点。

用户：大学教授和研究生
痛点：文献太多，人工阅读慢，容易错过重要研究
目标：自动分析文献，发现研究空白
```

**预期输出**：
- 追问清单（会连续提问）：
  - 用户会为此付费吗？有多少人真的需要这个？
  - 竞品是什么？为什么你能做得更好？
  - MVP最小能做成什么样？需要多长时间？
- 方案对比表

### `/plan-ceo-review` - CEO/投资人视角

**功能**：投资人/CEO视角，审定产品愿景、架构策略、风险清单

**使用示例**：
```
/plan-ceo-review

项目：AI文献分析工具
阶段：完成MVP开发，准备扩展
需要决策：下一步是增加功能还是扩大用户群？
```

**预期输出**：
1. 愿景对齐检查
2. 架构选型评审
3. 风险清单
4. 扩展方向建议

### `/plan-eng-review` - 工程视角

**功能**：工程视角，确认技术栈、项目结构、数据库选型、安全规则

**检测能力**：
- ✅ SQL注入
- ✅ LLM幻觉
- ✅ 数据OOM
- ✅ 认证漏洞

### `/review` - 代码和安全审查

**功能**：排查代码质量问题和安全漏洞

**检测能力**：
- ✅ SQL注入
- ✅ XSS漏洞
- ✅ 认证漏洞
- ✅ 性能问题（N+1查询）
- ✅ 代码异味

**使用示例**：
```
/review ./src

重点检查：
- 用户输入验证
- 数据库查询安全
- API鉴权逻辑
```

### 4. 项目沙盘推演、业务方案验证

- **效果**：提前发现业务漏洞和技术风险

## ⚠️ 注意事项

### 已知限制

1. **仅适配 Claude Code**
   - 影响：无法在其他IDE或平台使用
   - 解决：必须安装 Claude Code CLI

2. **需要真实项目需求**
   - 影响：模糊的需求会导致无效输出
   - 解决：准备具体用户案例、痛点数据

3. **数据库安全配置**
   - 影响：生产数据风险
   - 解决：**强制使用只读账户**，禁止可写权限

4. **文档需要人工复核**
   - 影响：自动生成内容可能不完全符合实际
   - 解决：结合自身业务调整，不要完全照搬

### 不适用场景

- ❌ **纯编程任务**（如"实现排序算法"）
  - 原因：Gstack 专注于产品设计流程
  - 替代：使用 Claude Code 原生功能

- ❌ **快速原型验证**（如"1小时做个Demo"）
  - 原因：Gstack 强调系统化设计，流程较重
  - 替代：使用 Cursor Composer

- ❌ **没有明确目标的项目**
  - 原因：Gstack 需要具体需求才能发挥作用
  - 替代：先明确项目方向

## 💬 常见问题

### Q1: Gstack 和其他 GStack 有什么区别？

A: 有两个不同的 Gstack：
- **本文档的 Gstack**：YC 总裁 Garry Tan 的 Claude Code 技能包，专注于产品设计和全流程开发
- [另一个 GStack](./gstack.md)：技术栈管理和项目脚手架工具

### Q2: 需要付费吗？

A: **完全免费**，这是一个开源项目。但需要：
- Claude Code CLI（Claude Pro 订阅）
- 安装 Gstack 技能包

### Q3: 支持哪些 Claude 模型？

A: 支持：
- Claude Opus 4.6（推荐复杂项目）
- Claude Sonnet 4.6（推荐日常使用）
- Claude Haiku 4.5（简单任务）

### Q4: 如何处理 LLM 幻觉问题？

A: Gstack 提供：
- 多模型交叉审查选项（Codex）
- 自动生成验证检查清单
- 输出数据来源追踪
