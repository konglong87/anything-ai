# 交互式世界模拟：能力边界与评估清单

> 画面能动，不等于世界能被稳定地操控。判断一套交互式模拟系统，关键是观察**你的操作是否改变了后续状态**，以及这些变化能否持续、自洽地呈现。

## 从视频到可交互环境

普通生成视频给出一段预先确定的画面；交互式世界模拟则尝试在运行时接收移动、观察或修改指令，并继续生成相应的视听反馈。两者都可能令人惊艳，但评价标准不同：前者重在成片质量，后者还要考察操作响应、场景记忆和多次交互后的稳定性。

不要仅凭一段录屏推断系统的内部实现、响应速度或长期可靠性。要判断这些能力，需要看到输入与输出的对应关系，并在相同条件下复测。

## 五个值得检查的能力

1. **操作响应**：连续改变视角与行进方向，记录指令到可见反馈的延迟。警惕忽快忽慢、镜头或物体突然跳变。
2. **状态连续**：离开一个位置后再返回，比较物件的位置、外观及遮挡关系。警惕物件消失、重生或空间布局前后矛盾。
3. **定向修改**：只要求改变一个局部属性，再检查其余场景是否保持不变。警惕修改扩散到无关区域，或已确认的状态丢失。
4. **视听联动**：触发动作、移动到不同位置，观察声音是否随事件和距离变化。警惕声音与动作错位，或对话对象与环境声混淆。
5. **多步行为**：连续下达有先后依赖的任务，观察中间步骤和最终结果。警惕只出现像是完成任务的画面，却无法保持过程与结果一致。

这些维度可以并行打标签，但**不能相互替代**：画面流畅不代表物理可信；一次正确响应也不代表多轮操作可靠。

## 一套可复用的测试办法

用自己设计的简单环境来测试，比换着看精美片段更容易发现问题。例如，在虚构的书房里预先确定桌上的杯子、墙上的钟和门的位置：

1. **先走动，再回看**：绕过桌子、离开房间再返回；核对三个物件是否还在原处。
2. **只改一件事**：要求改变杯子的颜色；核对钟、门与房间布局是否被意外改动。
3. **制造可听见的事件**：开关门并调整站位；观察事件顺序、画面动作和声音是否一致。
4. **重复至少三轮**：保持初始条件和操作顺序相同，分别记录成功与失败。次数是测试建议，不是对任何系统性能的测量结论。

一次失败不等于系统完全没有能力；一次成功也不能证明它能持续工作。记录条件、过程和反例，才能区分偶然的好片段与可复现的能力。

### 评估记录卡

| 项目 | 要记录什么 |
| --- | --- |
| 测试条件 | 环境描述、输入方式、操作顺序、设备及网络条件 |
| 观察结果 | 响应时间、状态变化、声音对应关系、可见异常 |
| 可复现性 | 相同条件下的重复次数、成功次数及差异 |
| 结论边界 | 哪些是直接观察，哪些仍是推测；尚未测试哪些情况 |

## 如何解读演示

- **短片只能显示被录下的时段**，不能证明长时间运行时仍保持同样的场景一致性。
- **看起来符合物理直觉**，不等于具备可用于工程验证的物理精度；碰撞、运动和物件持续性应分别测试。
- **有声音或对白**，不等于每次都能正确对应动作、位置和说话者。
- **看见复杂任务的结果**，不等于已经验证每个中间步骤，更不等于具备安全执行真实任务的能力。

阅读公开演示时，可把“直接看见的现象”“演示者的说明”和“自己推断的机制”分开记录。缺少操作记录、重复实验或失败样本时，不把宣传效果写成普遍结论。
