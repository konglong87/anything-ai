# 提示词检索修复与验收

日期：2026-10-21；基线：fbbe4db；上游固定源：4c245f7a43d143dcfbd194b768ee1c4d8aa8ff8d。

## 真实问题与复现

用户截图搜索「简洁」，内容类型停留在「术语」。线上清除所有筛选后，简洁 / 大方 / 界面仍是 0 条，后台仅 2 条；因此不能把问题归咎于用户筛选。复现见 before.json / before.jpg。

原因：
1. 原实现仅在标题、描述、别名等元数据中做空格切词和 includes，未搜索原文参数、约束、模板选项与展开依赖。
2. 不带空格的中文句子整体匹配；没有白话概念到专业材料的发现规则，也没有相关性排序。
3. 类型和领域是正确的 AND 筛选，但 UI 不揭示哪些匹配内容被过滤，零结果提示只能清空全部条件。
4. 上次测试覆盖的是少量预设导引词，并在测试里复制了一份简化检索函数，没有真正测试前端使用的实现；这是此次遗漏的重要原因。

## 架构与方案

- `scripts/jargon/search.mjs`：纯 JS 共享检索模块，前端与 Node 回归测试使用同一函数。分离归一化、中文分词、白话概念规则、字段权重排序与筛选诊断。
- 复用平台内建 Intl.Segmenter；无此能力时安全退化。评估了仓库已有的 MiniSearch：仅129条内容，索引扫描耗时小于毫秒，当前难点是语料与意图映射，额外引入倒排索引并不解决此问题，因此不增加运行依赖或网络服务。
- NFKC、大小写和标点归一化；中文概念优先最长词匹配，常用语气词剔除，未知词保留并要求全部有效词匹配。英语按词边界，防止 `capacit` 错中 `capacity`。
- 精确标题/别名优先，元数据高于原文正文，风格词优先具体极简/留白布局，后台优先Dashboard。词义关联是有限的、可维护的编辑规则，不是嵌入/AI语义检索，不声称理解任意自然语言或否定条件。
- 规范化增加 `searchText`，取独立条目正文、展开依赖与模板选项，不把统一提示词包装和固定来源链接当作搜索语料。215个锁定上游文件不改；与基线逐条比对，129项已有字段保持完全一致，仅新增检索语料字段。
- Vue 仅消费检索结果、展示筛选条件与诊断。零结果时区分「全库无匹配」和「被类型/领域挡住」，可保留关键词一键解除范围筛选，不暗中更改类型、不把设计模式重标成术语。
- 移动端将领域按钮收纳为同一个 domain 状态驱动的选择器；快捷词横向收纳，无页面横向溢出。
- 合集导出继续使用完整匹配集合，分页不影响导出；组合、复制、安全边界保持原实现。

- `npm test`：120项全部通过，包括新增47项检索回归。所有129个完整标题均能首位检索自身；每个上游/导引别名均可找回所属条目。覆盖白话、中文短句、标点、全角/中英、排序、正文参数/选项、未知词、类型/领域、无Segmenter降级及不修改prompt等。

- 20项最终构建真实浏览器断言通过，明细见 local.json：四个投诉词、短句与标点、专业词和正文色号、未知词、筛选恢复、快捷词、6条合集复制、检索→加入组合→填目标→复制、重置、分页、390px移动端、控制台错误检查。
